## 一、分工总览

5 人覆盖「后端 × 2 ｜ Android × 2（其一兼管理后台）｜ 测试 & 文档 × 1」：

| 编号 | 角色定位 | 主责模块 | 兼责 | 主责工作量 |
| --- | --- | --- | --- | --- |
| **成员 1** | **项目负责人 / 后端架构** | 后端架构、鉴权、数据库设计、部署、Code Review | 技术统筹、接口契约制定 | ≈ 14 人日 |
| **成员 2** | **后端开发** | 生活工具模块、第三方 API 对接、打卡积分、云端同步 | 测试环境维护、接口文档 | ≈ 13 人日 |
| **成员 3** | **Android 负责人** | Android 工程骨架、主题、网络/本地存储基座、核心页面、联调 | Android 技术攻关 | ≈ 15 人日 |
| **成员 4** | **Android 开发 + 管理后台** | 业务页面（待办/记账/个人中心）、桌面小组件、Vue3 管理后台 | Android 辅助、联调 | ≈ 14 人日 |
| **成员 5** | **测试 & 文档负责人** | 接口测试、测试用例、项目文档、Git 规范维护、联调验收 | 数据准备 / 前端辅助 | ≈ 12 人日 |

> 4 周周期内每人可用 ≈ 20 人日，上表人均 12~15 人日，留出了约 **25~30% 缓冲**用于联调、返工和答辩准备。

### 为什么这么分

- **后端 2 人**：后端是全项目的地基，工作量最大且**卡着 Android 端进度**，必须双人并行、及早交付接口。
- **Android 2 人**：客户端已收敛为**唯一交付端**，是用户能看到的一切，工作量最大，需要两人分工协作（一人搭骨架和核心页，一人做业务页与小组件）。
- **管理后台挂在 Android 成员名下**：后台工作量不大（≈11 人日）且相对独立，由工作量稍轻的成员 4 兼做，避免再单设一岗。
- **测试 & 文档独立 1 人**：测试与文档必须**贯穿全程**（不是最后才做），单独设岗才能保证接口一出来就有人验证。

## 二、成员职责明细

### 2.1 成员 1 —— 项目负责人 / 后端架构

**角色定位**：把握整体方向，负责后端骨架与"公共地基"，同时承担技术决策与代码评审。

**主责模块**

| 模块 | 说明 | 优先级 | 交付物 |
| --- | --- | --- | --- |
| 项目骨架 | FastAPI 工程搭建、分层结构、统一响应封装、全局异常处理 | P0 | 可运行的后端框架 |
| 账号体系 | 注册 / 登录 / JWT 鉴权 / 个人中心接口 | P0 | 鉴权接口 + 中间件 |
| 数据库设计 | ER 设计、建表、Alembic 迁移脚本 | P0 | 表结构文档 + 迁移脚本 |
| 部署与环境 | `local / test / prod` 三环境、部署脚本、CI | P0 | 部署文档 + 联调环境 |
| 代码评审 | 后端 PR 的 Review、接口契约把关 | 全程 | 评审记录 |

**负责目录 / 分支**：`backend/app/core`、`backend/app/api`、`backend/alembic`、`deploy/`；分支前缀 `feature/backend-*`

**关键职责**

- 第 1 周内产出**接口契约初稿 + 数据库表结构**，让 Android 端能立刻开工（不得拖到第 2 周）。
- 制定并维护**统一响应体与业务码表**，禁止各接口各写各的。
- 每周五组织 Code Review 与合并窗口。

**协作对象**：与成员 2 分接口；向成员 3 / 4 提供接口定义与联调环境。

### 2.2 成员 2 —— 后端开发

**角色定位**：负责后端业务主干，是"一站式"生活工具的落地者。

**主责模块**

| 模块 | 说明 | 优先级 | 交付物 |
| --- | --- | --- | --- |
| 生活工具接口 | 天气、时间 / 便民查询等接口封装 | P0 | 工具类接口 |
| 第三方 API 对接 | 选型、封装、超时重试、失败降级、缓存 | P0 | `integrations/` 模块 |
| 打卡积分系统 | 打卡记录、连续统计、积分流水、徽章判定 | P0 | 打卡积分接口 |
| 云端同步逻辑 | 云端数据 + 本地缓存同步策略 | P1 | 同步接口 |
| 接口文档维护 | Swagger 注解、错误码登记 | 全程 | 在线接口文档 |

**协作对象**：与成员 1 分工后端；向成员 3 / 4 交付接口。

## 六、分工原则与调整机制

### 6.1 原则

1. **一个模块一个主责人**：责任到人，避免"以为别人在做"。
2. **接口先定后写**：契约是各方唯一的对接依据。
3. **互备制**：每个模块至少两人能接手。
4. **组件先沉淀**：Android 公共组件由成员 3 统一产出，禁止各写各的。
5. **工作量均衡**：人均 12~15 人日，避免个别人成为瓶颈。
6. **文档随代码走**：改代码必须同步改文档。

### 6.2 进度落后怎么办

| 情况 | 处理方式 |
| --- | --- |
| 某成员任务拖后 ≤ 1 天 | 本人加班或互备人协助，站会说明 |
| 拖后 2~3 天 | 从 `P2` 砍任务，优先保 `P0`；互备人接手部分 |
| 长期阻塞（依赖他人） | 立即在站会提出，由成员 1 协调解阻塞 |
| 范围失控 | 冻结 `P2`，重启"第一梯队锁定"规则 |

### 6.3 任务认领

- 所有任务进看板（待办 / 进行中 / 待评审 / 已完成），标注 **负责人 + 组别 + 优先级**。
- 认领即负责，**变更负责人需在看板和群里同步**。
