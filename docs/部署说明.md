## 一、部署形态说明

本项目为 4 周课程/演示项目，**不使用 Docker、K8s 等重型方案**，采用最简单可靠的方式：

| 环境 | 部署方式 | 适用 |
| --- | --- | --- |
| local | 直接 `uvicorn --reload` | 开发调试 |
| test | 前台/后台运行 `uvicorn`，监听 `0.0.0.0` | 团队联调 |
| prod | `uvicorn` 多 worker + systemd/nssm 托管 | 交付演示 |

> 若最终答辩要求容器化，第 4 周有余量再补 `Dockerfile`。当前优先级是**能跑起来、能联调**。

## 二、首次部署步骤

### 2.1 准备环境

```bash
git clone <仓库地址>
cd Life\ Assistant/backend

# 创建虚拟环境
python -m venv .venv

# 安装依赖
./.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
# ./.venv/bin/python -m pip install -r requirements.txt          # macOS/Linux
```

### 2.2 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，至少改这三项：
#   APP_ENV
#   DATABASE_URL
#   JWT_SECRET_KEY
```

### 2.3 初始化数据库

```bash
# 确认 DATABASE_URL 指向正确
./.venv/Scripts/python.exe -m alembic upgrade head
```

### 2.4 启动服务

```bash
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 2.5 验证部署

```bash
# 健康检查
curl http://127.0.0.1:8000/health
# 期望：{"code":0,...,"data":{"status":"ok","database":"connected"}}

# 运行冒烟测试（推荐！能一次验证 44 项）
./.venv/Scripts/python.exe scripts/smoke_test.py
```

## 三、部署脚本

### 3.1 Windows：`deploy/start.bat`

见同目录文件。双击即可后台启动服务。

### 3.2 Linux/macOS：`deploy/start.sh`

见同目录文件。

### 3.3 迁移验证：`deploy/verify_migration.sh`

**这是最重要的一条**：验证迁移脚本能从**空数据库**完整跑通，再能滚回去。
在提交任何模型改动前都应该跑一次。

```bash
bash deploy/verify_migration.sh
```

## 四、日常运维

### 4.1 更新代码并重启

```bash
git pull
./.venv/Scripts/python.exe -m pip install -r requirements.txt  # 依赖有变时
./.venv/Scripts/python.exe -m alembic upgrade head              # 模型有变时
# 重启服务
```

### 4.2 查看日志

日志同时输出到控制台和 `logs/app.log`（按天切分，保留 14 天）：

```bash
tail -f logs/app.log
```

### 4.3 数据库备份（prod 必做）

```bash
# 备份
pg_dump -U life_app -h 127.0.0.1 life_assistant_prod > backup_$(date +%Y%m%d_%H%M).sql

# 恢复
psql -U life_app -h 127.0.0.1 life_assistant_prod < backup_20261010_1200.sql
```

SQLite 直接复制文件即可。

### 4.4 回滚

```bash
# 代码回滚
git checkout <上一个可用commit>
# 数据库回滚（谨慎！会丢数据）
./.venv/Scripts/python.exe -m alembic downgrade -1
```

## 五、交付前检查清单

第 4 周冻结版本时逐项确认：

- [ ] `alembic upgrade head` 在**全新空库**上执行成功
- [ ] `/health` 返回 `database: connected`
- [ ] `scripts/smoke_test.py` 全部通过
- [ ] `.env` 未被提交（`git status` 无 `.env`）
- [ ] `.env.example` 与代码实际读取的配置项一致
- [ ] `JWT_SECRET_KEY` 非默认值
- [ ] `DB_ECHO=false`、`LOG_LEVEL=INFO`
- [ ] `CORS_ORIGINS` 已按环境收窄
- [ ] 部署文档步骤可由他人照做复现
