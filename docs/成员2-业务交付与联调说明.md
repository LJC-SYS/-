## 三、给 Android 开发者（成员 3 / 成员 4）的联调对接指南

### 3.1 客户端 `client_id` 幂等规则（待办 / 备忘 / 记账）
- **客户端要求**：在本地离线或断网创建一条记录时，客户端本地使用 `UUID.randomUUID().toString()` 生成 `client_id` 保存于本地 Room 数据库。
- **服务端处理**：当网络恢复提交时，即使因弱网重试导致同一 `client_id` 提交多次，服务端也会自动识别并返回已有数据，**状态码为 200，不会新建多条脏数据**。

### 3.2 乐观锁版本号 `version` 与冲突处理
- 待办、备忘录、记账明细均带有 `version` 整数。
- 当客户端调用 `PATCH` 更新或 `DELETE` 删除时，**必须在请求体或 Query 参数中带上当前本地的 `version`**。
- 若服务端当前版本已被其他设备更新（`version` 不一致），服务端会返回业务错误码 `1407`（`SYNC_VERSION_CONFLICT`）。客户端收到 `1407` 后应提示用户并刷新重新获取。

### 3.3 天气容灾降级体验
- 响应字段包含 `from_cache`（布尔值）和 `degraded`（布尔值）。
- 若 `degraded == true`，表示第三方接口故障但成功提取到了过往缓存兜底，客户端可在 UI 顶部友好提示：`"网络异常，当前展示历史缓存天气"`。

### 3.4 增量同步联调流程（/sync/push 与 /sync/pull）
1. **本地离线变更推送 (`POST /sync/push`)**：
   - 客户端收集本地产生的变动数组，打包发送；
   - 采用**服务端优先 (Last-Write-Wins by server)** 策略；若某项版本过旧，服务端返回 `status = "conflict"` 并携带服务端的最新数据 `server_data`，其余成功项正常写入，不阻塞整批操作。
2. **增量拉取 (`GET /sync/pull`)**：
   - 客户端传入本地存储的上次同步时间 `since`（首次传 `1970-01-01T00:00:00+08:00`）；
   - 服务端返回自 `since` 之后创建、修改的所有实体；若实体被软删除，返回 `deleted = true`，客户端据此将本地 Room 对应记录移除。
