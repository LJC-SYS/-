## 一、怎么拿到本机 IP

### Windows

```bash
# 方法一：Git Bash
ipconfig | grep -A 8 "WLAN" | grep IPv4

# 方法二：直接看全部
ipconfig | findstr /i "IPv4"
```

找 `IPv4 地址`，通常是 `192.168.x.x` 或 `10.x.x.x`。

**注意**：如果有多个（虚拟机网卡、WSL、VPN），选**和同事在同一网段**的那个。判断方法：同事的 IP 前两段和你一样。

### 确认同事能访问

让同事执行：

```bash
ping 192.168.1.10
curl http://192.168.1.10:8000/health
```

ping 通但 curl 不通 → **防火墙问题**，见第三章。

## 二、开放防火墙端口（关键，最常忘）

Windows 默认会拦截外部访问 8000 端口。

**方法一：图形界面**

1. `Win + R` → 输入 `wf.msc` → 回车
2. 左侧「入站规则」→ 右侧「新建规则」
3. 类型选**端口** → 下一步
4. TCP → 特定本地端口填 `8000` → 下一步
5. 允许连接 → 下一步
6. 三个都勾（域/专用/公用）→ 下一步
7. 名称填 `Life Assistant Backend` → 完成

**方法二：命令行（管理员 PowerShell）**

```powershell
New-NetFirewallRule -DisplayName "Life Assistant Backend 8000" `
  -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

**方法三：临时关闭（仅调试，测完记得开回来）**

```powershell
# 查看当前状态
Get-NetFirewallProfile | Select-Object Name, Enabled
```

## 三、启动服务（联调模式）

联调环境必须监听 `0.0.0.0`，不能是 `127.0.0.1`（后者只有自己能访问）。

```bash
cd "D:/AAAAAAAA/Life Assistant/backend"

# 方式一：用脚本后台启动
bash deploy/start.sh --daemon

# 方式二：手动启动
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**启动前确认 `.env`**：

```ini
APP_ENV=test
APP_HOST=0.0.0.0
APP_PORT=8000
DATABASE_URL=postgresql+psycopg://life_app:密码@127.0.0.1:5432/life_assistant_test
JWT_SECRET_KEY=<测试环境独立密钥>
CORS_ORIGINS=*
LOG_LEVEL=INFO
DB_ECHO=false
```

**启动后自检**：

```bash
# 本地探活
curl http://127.0.0.1:8000/health

# 期望返回
# {"code":0,"message":"success","data":{"status":"ok","env":"test","database":"connected"},...}
```

`database` 必须是 `connected`，如果是 `disconnected` 说明数据库没连上，先修数据库再公布地址。

## 五、环境维护检查清单

每次公布地址前逐项确认：

- [ ] 服务监听 `0.0.0.0`（不是 `127.0.0.1`）
- [ ] 防火墙已放行 8000 端口
- [ ] `/health` 返回 `database: connected`
- [ ] 数据库迁移已执行到最新（`alembic current` 与 `alembic heads` 一致）
- [ ] `.env` 中 `APP_ENV=test`、`DB_ECHO=false`
- [ ] `JWT_SECRET_KEY` 非默认值且与 local 不同
- [ ] 冒烟测试通过（`python scripts/smoke_test.py`）
- [ ] 自己的 IP 没变（重启路由器/换网络会变）
- [ ] 已在群里公布地址 + 版本 + 已知问题

## 六、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 同事 ping 不通 | 不在同一网段 | 确认两边 IP 前两段一致 |
| ping 通但 curl 不通 | 防火墙拦截 | 见第二章放行端口 |
| 只有自己能访问 | 监听了 `127.0.0.1` | 改成 `--host 0.0.0.0` |
| `/health` 显示 disconnected | 数据库没起 / 连接串错 | 检查 PG 服务和 `DATABASE_URL` |
| 突然访问不了 | IP 变了 | 重新查 IP，重新公布 |
| 同事拿到 401 | 没带 Token | 检查 `Authorization: Bearer <token>` |
| 同事拿到 422 | 参数格式不对 | 看响应里 `data` 字段的详细校验错误 |
| 服务自己停了 | 终端关了 | 用 `bash deploy/start.sh --daemon` 后台启动 |

### 查看服务是否还在跑

```bash
# 看端口占用
netstat -ano | findstr :8000

# 看进程
tasklist | findstr python

# 看日志（后台启动时）
tail -f backend/logs/server.log
```

### 停止服务

```bash
# 后台启动的
kill $(cat backend/.server.pid)

# 或者按端口找进程杀掉
netstat -ano | findstr :8000
taskkill /PID <进程号> /F
```
