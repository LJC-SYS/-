## 二、通用响应规范

### 2.1 统一响应体

**所有**接口（含错误响应）返回 HTTP 200 以外的状态码与以下结构并存，业务结果一律看 `code`：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "a1b2c3d4e5f6",
  "timestamp": "2026-10-10T13:41:21+08:00"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | `0` 表示成功，非 0 为业务错误码，见第三章 |
| `message` | String | 面向用户或开发者的提示，成功固定为 `success` |
| `data` | Object/Array/null | 业务数据，无数据时为 `null` |
| `request_id` | String | 本次请求唯一标识，排查问题时提供给后端 |
| `timestamp` | String | 服务器时间 ISO 8601 带时区 |

> **Android 侧约定**：只判断 `code == 0`，不要用 HTTP 状态码判断业务成败。

### 2.2 HTTP 状态码使用

| 状态码 | 含义 | 说明 |
| --- | --- | --- |
| 200 | 成功 | 业务成功或业务失败均可能返回 200，看 `code` |
| 401 | 未认证 | Token 缺失、过期、无效。客户端应触发刷新或跳登录 |
| 403 | 无权限 | 已登录但无权访问（如普通用户访问管理接口） |
| 404 | 路径不存在 | 接口路径错误，非业务「数据不存在」 |
| 422 | 参数校验失败 | FastAPI 校验未过，`code` 为 `1001` |
| 500 | 服务器异常 | 未预期异常，`code` 为 `9999`，需附 `request_id` 报障 |
| 503 | 服务临时不可用 | 如数据库不可用 |

**业务层「数据不存在」「重复打卡」等一律用 200 + 业务码**，不要返回 404/400。

### 2.3 分页响应规范

请求参数（所有列表接口统一）：

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | Integer | 否 | 1 | 页码，从 1 开始，最小 1 |
| `page_size` | Integer | 否 | 20 | 每页条数，范围 1~100 |

响应结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "page_size": 20,
    "total": 0,
    "total_pages": 0
  },
  "request_id": "a1b2c3d4e5f6",
  "timestamp": "2026-10-10T13:41:21+08:00"
}
```

### 2.4 时间与金额

- 所有时间字段为 ISO 8601 带时区字符串，如 `2026-10-10T13:41:21+08:00`。
- 日期类字段（如打卡日期）为 `YYYY-MM-DD`。
- 金额字段为 `string` 类型，如 `"128.50"`，避免移动端浮点精度问题。

### 3.1 分段规则

| 区间 | 归属 | 负责人 |
| --- | --- | --- |
| `0` | 成功 | — |

| --- | --- | --- | --- | --- |
| 0 | 200 | `SUCCESS` | success | 成功 |
| 1001 | 422 | `PARAM_INVALID` | 参数校验失败 | 字段缺失、类型错误、格式不合法 |
| 1002 | 401 | `UNAUTHORIZED` | 请先登录 | 未带 Token |
| 1003 | 401 | `TOKEN_EXPIRED` | 登录已过期，请重新登录 | access token 过期 |
| 1004 | 401 | `TOKEN_INVALID` | 登录凭证无效 | Token 被篡改或格式错误 |
| 1005 | 403 | `FORBIDDEN` | 无访问权限 | 普通用户访问管理接口 |
| 1006 | 200 | `NOT_FOUND` | 数据不存在 | 业务数据未找到 |
| 1007 | 200 | `RESOURCE_CONFLICT` | 操作冲突，请刷新后重试 | 通用并发冲突 |
| 1008 | 429 | `TOO_MANY_REQUESTS` | 操作过于频繁，请稍后再试 | 触发限流 |
| 1009 | 200 | `DATA_CORRUPTED` | 数据异常，请联系管理员 | 数据不一致 |
| 9999 | 500 | `INTERNAL_ERROR` | 服务器开小差了，请稍后再试 | 未捕获异常 |

| 1103 | 200 | `USERNAME_EXISTS` | 该用户名已被占用 | 注册重名 |
| 1104 | 200 | `EMAIL_EXISTS` | 该邮箱已被注册 | 注册邮箱重复 |
| 1105 | 200 | `PHONE_EXISTS` | 该手机号已被注册 | 注册手机号重复 |
| 1106 | 200 | `ACCOUNT_DISABLED` | 账号已被禁用 | `status = disabled` |
| 1107 | 200 | `ACCOUNT_DELETED` | 账号已注销 | `status = deleted` |
| 1108 | 200 | `REFRESH_TOKEN_INVALID` | 刷新凭证无效，请重新登录 | refresh token 无效/已吊销 |

## 四、鉴权机制

### 4.1 Token 方案（已定稿）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 算法 | HS256 | 密钥走环境变量 `JWT_SECRET_KEY`，不入库不进仓库 |
| Access Token 有效期 | 2 小时 | 放 `Authorization` 头 |
| Refresh Token 有效期 | 14 天 | 落库 `refresh_tokens`，存哈希 |
| 刷新策略 | 轮换（Rotation） | 每次刷新签发新 refresh，旧的同时吊销 |
| 重复使用旧 refresh | 全部吊销该用户该设备 token | 防盗用 |

Access Token Payload：

```json
{
  "sub": "10001",
  "username": "alice",
  "role": "user",
  "type": "access",
  "iat": 1760000000,
  "exp": 1760007200,
  "jti": "b1c2d3e4"
}
```

### 4.2 客户端处理约定

| 场景 | `code` | Android 侧动作 |
| --- | --- | --- |
| Token 过期 | 1003 | 静默用 refresh 换新 token，重放原请求；失败则跳登录 |
| Token 无效 | 1004 | 直接清本地登录态，跳登录 |
| Refresh 失效 | 1108 / 1109 | 清登录态，跳登录 |
| 无权限 | 1005 | 提示「无权限」，不跳登录 |

### 4.3 游客模式

游客数据**不存在云端**，全部在 Android 本地（Room）。因此：
- 不提供游客专用接口。
- 游客转正式用户时，由 Android 调用注册/登录接口后，**用正式 Token 批量上传本地数据**（走第九章同步接口，靠 `client_id` 幂等）。

### 6.2 注册

`POST /api/v1/auth/register` · 无需鉴权

请求体：

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| `username` | String | 是 | 4~20 位，字母/数字/下划线，唯一 |
| `password` | String | 是 | 8~32 位，必须同时含字母和数字 |
| `email` | String | 否 | 邮箱格式，唯一（三选一凭证中至少填一个） |
| `phone` | String | 否 | 11 位中国大陆手机号，唯一 |
| `nickname` | String | 否 | 1~20 位，不填默认等于 `username` |

> `email` 与 `phone` 至少填一项。登录凭证采用**三选一识别**，详见 4.1 与技术决策说明。

请求示例：

```json
{
  "username": "alice",
  "password": "abc12345",
  "email": "alice@example.com",
  "nickname": "小爱"
}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user_id": 10001,
    "username": "alice",
    "nickname": "小爱",
    "access_token": "eyJhbGciOi...",
    "refresh_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200
  },
  "request_id": "a1b2c3d4e5f6",
  "timestamp": "2026-10-10T13:41:21+08:00"
}
```

可能错误码：`1001`、`1103`、`1104`、`1105`、`1110`、`1111`

> 注册成功直接返回 Token，客户端无需再调登录。

### 6.3 登录

`POST /api/v1/auth/login` · 无需鉴权

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | String | 是 | 用户名 / 邮箱 / 手机号，服务端自动识别 |
| `password` | String | 是 | 密码 |
| `device_id` | String | 否 | 设备标识，用于多设备 Token 管理 |

**识别规则（服务端）**：含 `@` → 按邮箱查；纯 11 位数字且以 1 开头 → 按手机号查；否则按用户名查。

请求示例：

```json
{ "account": "alice@example.com", "password": "abc12345", "device_id": "android-abc123" }
```

响应：同 6.2 注册响应结构。

可能错误码：`1001`、`1101`、`1102`、`1106`、`1107`

> 安全约定：账号不存在与密码错误对外**统一返回 `1102`**（避免账号枚举），但日志中区分记录。

### 6.4 刷新 Token

`POST /api/v1/auth/refresh` · 无需鉴权

请求体：

```json

    "results": [
      { "client_id": "5f8d1e2a-...", "entity_type": "todo", "status": "created", "server_id": 30001, "version": 1 },
      { "client_id": "6a9e2f3b-...", "entity_type": "todo", "status": "updated", "server_id": 30002, "version": 3 },
      { "client_id": "7b0f3a4c-...", "entity_type": "memo", "status": "conflict", "server_id": 40001, "server_version": 5, "server_data": { "title": "服务器版本" } }
    ],
    "partial_failure": true,
    "server_time": "2026-10-10T13:41:21+08:00"
  },
  "request_id": "a1b2c3d4e5f6",
  "timestamp": "2026-10-10T13:41:21+08:00"
}
```

`status` 取值：

| status | 含义 | 客户端动作 |
| --- | --- | --- |
| `created` | 新建成功 | 记录 `server_id` 与 `version` |
| `updated` | 更新成功 | 更新本地 `version` |
| `deleted` | 删除成功 | 移除本地记录 |
| `skipped` | 幂等命中/无变化 | 静默忽略 |
| `conflict` | 版本冲突 | 用 `server_data` 覆盖本地 或 提示用户（**采用服务端优先**） |

> **冲突策略（已定稿）**：服务端优先（Last-Write-Wins by server）。返回 `conflict` 时同时给出 `server_data` 与 `server_version`，客户端直接覆盖本地并提示「该内容已在其他设备更新」。
> **部分失败约定**：单个变更失败不影响其他变更，`partial_failure = true` 时客户端应对失败项重试，成功项不再重传。

### 8.2 拉取增量

`GET /api/v1/sync/pull` · 需鉴权

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `since` | String | 是 | 上次同步时间，ISO 8601；首次传 `1970-01-01T00:00:00+08:00` |
| `entity_types` | String | 否 | 逗号分隔，如 `todo,memo`，不传则全部 |
| `limit` | Integer | 否 | 默认 200，上限 500 |

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "server_time": "2026-10-10T13:41:21+08:00",
    "has_more": false,
    "changes": [
      { "entity_type": "todo", "server_id": 30001, "client_id": "5f8d1e2a-...", "version": 1, "deleted": false, "updated_at": "2026-10-10T13:41:21+08:00", "data": { "title": "买菜" } },
      { "entity_type": "memo", "server_id": 40001, "client_id": "7b0f3a4c-...", "version": 5, "deleted": true, "updated_at": "2026-10-10T13:41:00+08:00", "data": null }
    ]
  },
  "request_id": "a1b2c3d4e5f6",
  "timestamp": "2026-10-10T13:41:21+08:00"
}
```

> `has_more = true` 时客户端用返回的最后一条 `updated_at` 作为新的 `since` 继续拉取。
> `deleted = true` 的条目：客户端应删除本地记录（对应软删除）。
