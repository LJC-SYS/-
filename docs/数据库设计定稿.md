## 一、v1.0 → v1.1 变更说明

v1.0 为可执行初稿，文末第十二章列了 11 项待确认事项。本次按团队决策收敛如下：

| # | v1.0 待确认事项 | v1.1 定稿结论 | 决策依据 |
| --- | --- | --- | --- |
| 1 | 登录凭证用哪种 | **用户名为必填，邮箱/手机号至少填一项；登录时三选一自动识别** | 三字段均已建唯一索引，识别成本低，用户体验好 |
| 2 | JWT 是否用 Refresh Token | **使用**。access 2 小时 / refresh 14 天，建 `refresh_tokens` 表 | 原生 App 生命周期长，避免频繁重登 |
| 3 | 游客数据是否转入正式账号 | **允许**。游客数据存 Android 本地，注册/登录后用正式 Token 批量上传 | 走同步接口 `client_id` 幂等，无需游客专用接口 |
| 4 | 备忘录是否必须云同步 | **支持**（P1） | 多设备场景需要 |
| 5 | 待办/记账是否多设备同步 | **支持**（P1） | 同上 |
| 6 | 同步冲突策略 | **服务端优先（LWW by server）**，返回冲突时附 `server_data` | 实现简单，4 周项目不引入复杂合并 |
| 7 | 积分规则写代码还是后台配置 | **代码内配置（`point_rules` 表不建）**，后台只读展示 | 4 周项目规则变更少，后台可写增加复杂度 |
| 8 | 后台内容管理范围 | **公告 / 帮助 / 轮播**，统一存 `content_items` | 复用同一表，靠 `content_type` 区分 |
| 9 | 天气缓存 PG 还是 Redis | **PostgreSQL `weather_cache` 表**，不引 Redis | 查询量级不需要 Redis，省部署与运维成本 |
| 10 | 用户注销数据保留规则 | **软删除 `status = deleted`，业务数据保留，不在首版做匿名化** | 首版无真实用户，避免过度设计 |
| 11 | 目标数据库 | **PostgreSQL 14+**；本地开发可临时 SQLite | 团队统一，PG 支持 JSONB 与 TIMESTAMPTZ |

## 二、通用设计约定（执行版）

1. 主键统一 `BIGINT`，字段名 `id`。
   - **实现细节**：SQLite 下使用 `BigInteger().with_variant(Integer, "sqlite")`。
     SQLite 只有 `INTEGER PRIMARY KEY` 支持自增，直接用 BIGINT 会导致 `NOT NULL constraint failed: users.id`。PG 下仍为 BIGINT。
2. 时间统一带时区，PG 用 `TIMESTAMPTZ`，业务时区 `Asia/Shanghai`。
3. 所有业务表含 `created_at`、`updated_at`。
4. 需离线同步的表（`todos`/`memos`/`accounting_records`）增加 `client_id`、`version`、`deleted_at`。
5. 金额用 `NUMERIC(12,2)`，禁止浮点；**接口层用字符串传输**。
6. 密码只存 bcrypt 哈希。
7. API Key、Token 等敏感配置不入库、不进仓库。
8. 字段小写蛇形命名。
9. 枚举用字符串 + 应用层校验，不用数据库枚举类型。
10. 外键字段建索引，常用筛选排序建联合索引。

## 四、事务与一致性要求

### 4.1 打卡事务（成员 2 实现）

同一事务内完成，任一步失败整体回滚：

1. 检查当天是否已打卡
2. 写入 `checkin_records`
3. 写入 `point_transactions`
4. 更新 `users.points_balance`
5. 判断并发放徽章，写入 `user_badges`

> `uq_checkin_user_date` 是并发防重的最后防线，即使应用层校验漏掉也会被数据库拦住。

### 4.2 后台积分调整（成员 4 实现）

写流水 + 更新余额 + 记录 `operator_id` 与原因，需同事务。
若启用审计表，同时写 `admin_operation_logs`。

### 4.3 删除策略

| 数据 | 策略 |
| --- | --- |
| 用户设置 | 删除用户时级联清理 |
| 待办 / 备忘录 / 记账 | **软删除**（`deleted_at`），保证同步正确 |
| 积分流水、操作日志 | **不删除**（审计数据） |
| 用户账号 | 软删除（`status = deleted`） |
